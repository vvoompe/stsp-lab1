# Лабораторна робота № 1. Низькорівневе введення/виведення та робота з файловою системою

Дисципліна: «Сучасні технології системного програмування», ФІТ КНУ, 2026 р.
Виконав: Маркграф Олександр, група ІПЗ-31 (підгрупа 1).

Аналоги системних утиліт `cp` і `grep`, а також обхід дерева каталогів із збором
метаданих - реалізовані мовою C на базових системних викликах Linux.
Функції високого рівня (`fopen`, `fread`, `fwrite`, `fseek`, `stdio`-потоки,
`system()`, `popen()`) не використовуються: уся робота з файлами йде через
файлові дескриптори.

## Склад роботи

| Файл | Призначення |
| --- | --- |
| `src/common.h`, `src/common.c` | спільні засоби: повідомлення про помилки через `errno`/`strerror()`, повний запис буфера, форматування прав/розміру/часу |
| `src/mycp.c` | аналог `cp` | 
| `src/mygrep.c` | аналог `grep` |
| `src/mytree.c` | обхід дерева каталогів із метаданими (аналог `tree`/`ls -lR`) |
| `Makefile` | збірка, `make test`, `make demo` |
| `tests/selftest.sh` | самоперевірка: 31 перевірка, результати звіряються з `cp`/`grep`/`find`/`stat` |
| `tests/demo.sh` | демонстраційний прогін для захисту роботи |

## Збірка та запуск

```bash
make                 # збирає mycp, mygrep, mytree (gcc -std=gnu11 -Wall -Wextra -O2)
make test            # самоперевірка: PASS=31 FAIL=0
make demo            # демонстрація з підготовленим тестовим деревом
```

## Використані системні виклики

| Утиліта | Системні виклики |
| --- | --- |
| `mycp` | `open()`, `read()`, `write()`, `close()`, `lseek()`, `fstat()`, `ftruncate()`, `fchmod()`, `futimens()` |
| `mygrep` | `open()`, `read()`, `write()`, `close()`, `lseek()`, `fstat()` |
| `mytree` | `opendir()`, `readdir()`, `closedir()`, `dirfd()`, `fstat()`, `stat()`, `lstat()`, `readlink()`, `write()` |

Обробка помилок у всіх трьох утилітах: код помилки береться з `errno`, текст -
через `strerror()` (аналогічно `perror()`), повідомлення має вигляд
`mycp: не вдалося відкрити джерело 'файл': No such file or directory`,
а програма повертає ненульовий код завершення.

## mycp - аналог cp

```bash
mycp [-nvpS] [-b РОЗМІР] ДЖЕРЕЛО ... ПРИЗНАЧЕННЯ
```

- `-n` - не перезаписувати наявний файл призначення (`open()` з `O_EXCL`);
- `-p` - зберегти права доступу та часи (`fchmod()`, `futimens()`);
- `-S` - копіювати розріджені файли зі збереженням «дірок»
  (`lseek(fd, off, SEEK_DATA)` / `SEEK_HOLE` + `ftruncate()`);
- `-b` - розмір буфера читання/запису (типово 64 КіБ); `read()`/`write()`
  викликаються в циклі, часткові записи дописуються.

```
$ make demo
$ mycp -v demo/data/random.bin copy/
'demo/data/random.bin' -> 'copy/random.bin' (293.0 КіБ)
$ mycp -v -S demo/data/sparse.img copy/sparse_mycp.img
'demo/data/sparse.img' -> 'copy/sparse_mycp.img' (8.0 МіБ, фактично прочитано 4.0 КіБ - дірки збережено)
$ mycp demo/data/немає_такого copy/x
mycp: не вдалося відкрити джерело 'demo/data/немає_такого': No such file or directory
```

## mygrep - аналог grep

```bash
mygrep [-ivcnqswb] ШАБЛОН [ФАЙЛ ...]
```

- `-i` ігнорувати регістр (власна обробка ASCII та кирилиці UTF-8);
- `-v` інвертувати збіг, `-c` лише кількість, `-n` номер рядка, `-w` ціле слово;
- `-b` зміщення рядка в байтах - визначається через `lseek(fd, 0, SEEK_CUR)`;
- `-q` тихий режим, `-s` придушити помилки читання;
- коди завершення як у справжнього `grep`: 0 - знайдено, 1 - не знайдено, 2 - помилка;
- рядки збираються вручну з буфера `read()`, тому довжина рядка не обмежена;
- дескриптор перевіряється через `fstat()`: для каналу/термінала `lseek()` не
  викликається (там він завершується помилкою `ESPIPE`).

```
$ mygrep -n kernel demo/data/kernel.log
2:kernel: усі повідомлення
3:kernel: ще один рядок
$ diff <(mygrep -n kernel demo/data/kernel.log) <(grep -n kernel demo/data/kernel.log)
(порожньо - вивід збігається)
```

## mytree - обхід дерева каталогів

```bash
mytree [-almb] [-d ГЛИБИНА] [ШЛЯХ ...]
```

Для кожного об'єкта збираються тип, права доступу, розмір і час останньої
модифікації: `lstat()` дає інформацію про сам об'єкт (не розкриваючи символьні
посилання), `fstat(dirfd(dp))` - метадані каталогу через дескриптор, який
`opendir()` тримає відкритим. `readdir()` повертає `NULL` і в кінці каталогу, і
при помилці - розрізняємо за `errno`. Помилка доступу до окремого каталогу
(`EACCES`) не зупиняє обхід.

```
$ mytree demo
demo
├── drwxrwxr-x   4.0 КіБ  2026-09-23 13:34:40  data/
│   ├── -rw-rw-r--        37 Б  2026-09-23 13:34:40  fruit.txt
│   ├── -r--------        86 Б  2026-09-23 13:34:40  kernel.log
│   ├── -rw-rw-r-- 293.0 КіБ  2026-09-23 13:34:40  random.bin
│   └── -rw-rw-r--   8.0 МіБ  2026-09-23 13:34:40  sparse.img
├── drwxrwxr-x   4.0 КіБ  2026-09-23 13:34:40  docs/
│   └── -rw-rw-r--       118 Б  2026-09-23 13:34:40  readme.txt
├── drwxrwxr-x   4.0 КіБ  2026-09-23 13:34:40  links/
│   └── lrwxrwxrwx        18 Б  2026-09-23 13:34:40  readme.link -> ../docs/readme.txt
└── drwxrwxr-x   4.0 КіБ  2026-09-23 13:34:40  src/
    ├── -rw-rw-r--        48 Б  2026-09-23 13:34:40  main.c
    ├── drwxrwxr-x   4.0 КіБ  2026-09-23 13:34:40  sub/
    │   └── -rw-rw-r--        26 Б  2026-09-23 13:34:40  deep.c
    └── -rw-rw-r--        34 Б  2026-09-23 13:34:40  util.c

Разом: каталогів 6, звичайних файлів 8, посилань 1, інших 0; сумарний розмір файлів 8.3 МіБ
```

`mytree -m` виводить плоский список метаданих (права, розмір, час, шлях) -
зручно для подальшої обробки; `-b` показує розміри в байтах.

## Особливості реалізації, які варто показати

- усі дані пишуться через `write()`, тому порядок рядків не залежить від
  буферизації `stdio` (змішувати `printf()` і `write()` небезпечно);
- `read()`/`write()` повторюються при `EINTR`, частковий запис дописується;
- `-S` у `mycp` не читає «дірки»: файл на 8 МіБ із однією діркою копіюється
  читанням 4 КіБ і займає стільки ж блоків, як `cp --sparse=always`;
- `mygrep -b` показує зміщення, обчислене через `lseek()`, і воно збігається з
  системним `grep -b`;
- `mytree` не падає на каталозі без прав доступу, а друкує
  `Permission denied` (з `errno`) і продовжує роботу.
